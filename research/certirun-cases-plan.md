# CertiRun Cases Plan

## Cases Job

Cases should build trust through execution patterns and visible evidence, not through invented success stories or unsupported testimonials.

## Case Pattern Template

Each case should follow this structure:

1. Starting Point
2. What Was Unclear
3. What CertiRun Organized
4. Visible Outputs
5. Buyer-Side Value
6. Evidence Notes

## Acceptable Evidence Types

- redacted communication trace
- redacted quotation comparison headers
- packing or label checklist
- document checklist
- dispatch update format
- anonymized workflow timeline

## Restricted Claims

Do not publish:

- fake customer names
- fake order values
- fake shipment records
- fake screenshots
- unsupported certification claims
- unsupported lead time, price, stock, or MOQ claims

## Testimonial Rule

Testimonials may support a case only when they are real, approved, and not the main evidence. Execution trace should carry the trust.

## QA Status

Recommended statuses:

- `draft`
- `needs_review`
- `approved_for_publish`

Any case with a real customer claim should require human review before publication.
